# Output

Everything a command writes. **Delete the whole directory whenever you like** — that is
the contract, and it is tested: every deck in this repo rebuilds from source alone.

If something in here cannot be regenerated by re-running a command, it is in the wrong
place. Move it to [`authoring/`](../authoring/README.md) if it is yours, or
[`examples/`](../examples/README.md) if it belongs to the library.

```
out/
  my-deck/
    My Deck v1.pptx            the deck
    My Deck v1.manifest.json   what `qa` reads; it pairs with the deck by name
    My Deck v1.content.md      the same build as words, for a human to read
    My Deck v1.beats.md        the same build as its reveal order, click by click
    render/                    slide-NNN.jpg, the PDF, qa.md, qa.json, contact sheets
    .build/                    generated inputs and intermediates, hidden on purpose
  conform/<template>/          a derived theme, the exercise deck, and its .build/
```

**One directory per deck, not one directory of decks.** `render` and `qa` write beside
the `.pptx` they are given, so two decks in one directory render into the same `render/`
and overwrite each other's slides — silently, leaving only the last one built.

**`.build/` is why the rest is readable.** A `.pptx` embeds every picture it places, so
once a deck exists the sources that fed it are scratch. The assembled spec and any
generated imagery go there; the deck's own directory shows the deck, the manifest, and
the render you look at.

**Every build keeps the spec that made it**, as `.build/<deck name>.deck.yaml` — one per
version, so an edited spec still rebuilds every earlier version. That is what makes the
delete-whenever-you-like contract above true rather than aspirational.
It carries the spec and nothing else: a deck that names an `extends:` module, a
`document:` source or its own images still needs those files to rebuild.

Only this README is committed, so the note survives the wipe it describes.
